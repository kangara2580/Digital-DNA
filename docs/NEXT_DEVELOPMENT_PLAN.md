# Next Development Plan

작성일: 2026-05-01

목표: 현재 Admin 1차 콘솔을 실제 운영 가능한 제품 백오피스로 분리하고, 사이트 전체 데이터 흐름을 DB 중심으로 안정화한다.

## 1. 지금 바로 필요한 수정

| 우선순위 | 작업 | 이유 |
| --- | --- | --- |
| 1 | Admin 레이아웃 충돌 수정 | 기존 사이트 왼쪽 아이콘 레일이 Admin 패널을 가리던 문제 해결 |
| 2 | Admin 한글 깨짐 정리 | 운영자가 읽을 수 있어야 하므로 깨진 문자열 전면 정리 |
| 3 | `/admin/videos` 분리 | 영상/이미지 검수와 수정 폼이 커져서 독립 페이지가 필요 |
| 4 | Admin 검색/필터 | 영상, 회원, 구매, 신고를 상태/키워드로 찾아야 함 |
| 5 | 페이지네이션 | 데이터가 늘면 최근 12개만 보는 구조는 부족 |

## 2. 다음 개발 큰 묶음

### A. Admin 화면 구조 정리

현재 `/admin` 한 페이지에 모든 기능이 모여 있다. 장기적으로는 아래처럼 나눠야 한다.

| 페이지 | 역할 |
| --- | --- |
| `/admin` | 전체 요약, 오늘 처리할 일 |
| `/admin/videos` | 영상/이미지 검수, 정보 수정, 상태 변경 |
| `/admin/users` | 회원 검색, 제재, 메모, 활동 내역 |
| `/admin/purchases` | 구매/환불/취소 상태 관리 |
| `/admin/reports` | 신고 처리, 대상 영상/회원 연결 |
| `/admin/jobs` | AI 생성 작업 조회, 실패 재시도 |
| `/admin/audit-logs` | 관리자 행동 기록 검색 |
| `/admin/settings` | 운영 정책, 관리자 권한 |

첫 구현 추천: `/admin/videos`

이유:

- 현재 가장 UI가 복잡하다.
- 이미지/영상 검수, 정보 수정, 상태 변경, 메모, 이력이 모두 연결된다.
- 공개 노출 정책과 직접 연결된다.

### B. 영상/이미지 수정 구조 고도화

필요 기능:

1. 영상 검색
2. 상태 필터: `approved`, `pending`, `rejected`, `hidden`
3. 카테고리 필터
4. 판매자 필터
5. 수정 이력 보기
6. 운영 메모 보기/작성
7. 대량 승인/숨김

추가로 필요한 정책:

- 판매자가 수정하면 `pending`
- Admin이 수정하면 즉시 반영
- 원본 영상 URL이나 썸네일 URL 변경은 항상 `content_change_logs`에 기록
- hidden 영상은 공개 피드에서 제외

### C. 회원 상세 구조

회원정지보다 먼저 필요한 것은 “회원 상세 화면”이다. 정지를 하려면 그 회원의 구매, 신고, 리뷰, AI 작업을 같이 봐야 한다.

필요 섹션:

| 섹션 | 보여줄 내용 |
| --- | --- |
| 프로필 | 이메일, 닉네임, 전화번호, 국가, 가입/수정일 |
| 구매 | 구매 영상, 금액, 상태 |
| 판매 | 판매 영상, 상태, 판매수 |
| 리뷰 | 작성 리뷰 |
| 신고 | 신고한 내역, 신고 받은 내역 |
| AI 작업 | 생성 작업, 실패 작업 |
| 운영 메모 | 내부 메모 |
| 제재 | 현재 활성 제재 |

### D. 공개 화면 DB 중심 전환

현재 사이트는 코드 카탈로그와 DB 영상이 섞여 있다. 제품이 커지면 DB 중심으로 바꿔야 한다.

필요 작업:

1. 코드 카탈로그는 초기 seed 데이터로만 사용
2. 공개 피드/검색/카테고리는 DB `videos` 기준으로 조회
3. `approved`만 공개 노출
4. 카테고리, 최신순, 인기순, 가격순 정렬을 DB 쿼리로 처리
5. 카탈로그 동기화는 Admin 전용 도구로 유지

### E. 구매/환불/정산 구조 분리

현재 `purchases.status`는 구매 상태만 다룬다. 실제 운영에서는 정산이 따로 필요하다.

필요 테이블 후보:

- `settlements`
- `refund_requests`
- `payment_events`

정책:

- 구매 완료와 판매자 정산은 별개
- 환불 요청은 바로 환불 처리하지 않고 요청/검토/승인 단계로 분리
- 환불 처리 시 구매 상태와 정산 상태를 함께 갱신
- finance 권한이 있는 Admin만 환불/정산 처리

### F. 신고/검수 자동화

필요 정책:

- 같은 영상 신고 3회 이상이면 자동 `pending`
- 저작권 신고는 Admin 검수 우선순위 높음
- 신고 처리 시 영상/회원/판매자 리스크 점수 갱신
- 신고 처리 결과는 신고자에게 알림

### G. AI 작업 운영

필요 기능:

- 실패 작업 재시도
- 사용자별 AI 생성 횟수 제한
- AI 작업 비용 기록
- 결과물 신고/숨김
- 부적절한 작업 입력 차단

## 4. 이번 다음 턴에서 바로 개발할 추천 범위

| 작업 | 결과 |
| --- | --- |
| Admin 레이아웃 완전 고정 | 왼쪽 패널이 항상 보임 |
| 깨진 Admin 한글 문자열 정리 | 운영자가 읽을 수 있는 화면 |
| `/admin/videos` 페이지 생성 | 영상 검수 기능 분리 |
| 영상 검색/상태 필터 | pending/hidden 등을 빠르게 찾음 |
| 페이지네이션 | 데이터가 많아져도 안정적 |

이 범위를 끝내면 Admin은 “보기 좋은 한 페이지”에서 “실제로 운영자가 매일 쓰는 도구”로 한 단계 올라간다.
