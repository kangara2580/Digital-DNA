# Admin Operations Master Plan

작성일: 2026-05-01

목표: Admin을 단순 대시보드가 아니라 실제 운영자가 회원, 이미지/영상, 구매, AI 작업, 신고, 감사 로그를 확인하고 처리할 수 있는 운영 콘솔로 만든다.

## 1. Admin이 관리해야 하는 전체 영역

| 영역 | DB 기준 | Admin에서 해야 할 일 | 우선순위 |
| --- | --- | --- | --- |
| 회원 | `profiles` | 회원 목록, 이메일/닉네임/연락처/국가/최근 수정일 확인 | 높음 |
| 이미지/영상 | `videos.poster`, `videos.src` | 썸네일 확인, 원본 링크 확인, 승인/반려/숨김 처리 | 높음 |
| 구매 | `purchases` | 구매자/판매자/영상/금액/상태 확인, 환불/취소 상태 변경 | 높음 |
| AI 작업 | `generation_jobs` | 작업 상태, 진행률, 실패 사유, 결과 URL 확인 | 높음 |
| 신고/검수 | `reports` | 신고 대상/사유 확인, 처리 완료/재오픈, 관리자 메모 | 중간 |
| 관리자 기록 | `admin_audit_logs` | 누가 어떤 데이터를 바꿨는지 확인 | 높음 |
| 사용자 저장 데이터 | `user_data_blobs` | 사용자별 저장 데이터 키와 갱신 시각 확인 | 중간 |

## 2. 운영 화면 구조

첫 단계에서는 `/admin` 한 화면에 핵심 운영 패널을 모두 배치한다. 이후 데이터가 많아지면 `/admin/users`, `/admin/videos`, `/admin/purchases`처럼 독립 페이지로 분리한다.

| 섹션 | 화면 내용 | 처리 기능 |
| --- | --- | --- |
| Overview | 회원 수, 영상 수, 구매 수, AI 작업 수, 신고 수, 감사 로그 수 | 없음 |
| Members | 최근 회원 목록 | 1차는 조회, 2차에서 정지/권한 변경 |
| Media Review | 영상 썸네일/원본/판매자/가격/상태 | 승인, 반려, 숨김 |
| Purchases | 구매자, 판매자, 영상, 금액, 상태 | paid/refunded/canceled 변경 |
| AI Jobs | 상태, 단계, 진행률, 결과 URL, 오류 | 1차는 조회, 2차에서 재시도 |
| Reports | 신고자, 대상, 사유, 상태, 메모 | 처리 완료, 재오픈 |
| Audit Logs | 관리자 액션 기록 | 조회 |

## 3. DB 확장 계획

현재 `videos`에는 운영 검수 상태가 없다. Admin에서 실제 승인/반려를 하려면 아래 컬럼이 필요하다.

| 컬럼 | 목적 |
| --- | --- |
| `status` | `approved`, `pending`, `rejected`, `hidden` 중 하나 |
| `moderation_reason` | 반려/숨김 사유 |
| `approved_at` | 승인 시각 |
| `approved_by` | 승인한 관리자 ID |

기존 영상은 이미 사이트에 노출 중이므로 migration 적용 시 기본값은 `approved`로 둔다. 새 판매자 업로드는 다음 단계에서 `pending`으로 들어오게 바꾼다.

## 4. 권한 원칙

1. Admin 화면은 `ADMIN_EMAILS` 또는 `ADMIN_USER_IDS`에 포함된 사용자만 접근한다.
2. 중요한 변경은 모두 `admin_audit_logs`에 기록한다.
3. 화면에서 숨기는 것과 별개로, 서버 액션에서도 Admin 권한을 다시 확인한다.
4. 구매/환불/숨김/승인 같은 변경은 즉시 DB에 반영하고, 변경 전/후 값을 감사 로그에 남긴다.

## 5. 이번 1차 개발 범위

이번 작업에서 바로 구현할 것:

| 작업 | 결과 |
| --- | --- |
| 영상 moderation 컬럼 추가 | Admin이 승인/반려/숨김 상태를 저장할 수 있음 |
| Admin 감사 로그 helper 추가 | 모든 Admin 변경을 `admin_audit_logs`에 저장 |
| Admin 데이터 loader 추가 | 회원/영상/구매/AI/신고/로그를 한 번에 조회 |
| Admin server actions 추가 | 영상 상태, 구매 상태, 신고 상태 변경 |
| `/admin` 화면 재구성 | 실제 운영자가 읽을 수 있는 한국어 UI와 처리 버튼 제공 |

## 6. 다음 2차 개발 범위

| 작업 | 설명 |
| --- | --- |
| `/admin/users` 분리 | 회원 검색, 정지, 메모 기능 |
| `/admin/videos` 분리 | 영상 검수 큐, 미리보기, 대량 승인 |
| `/admin/purchases` 분리 | 환불 사유, 정산 상태, 결제사 연동 |
| `/admin/reports` 분리 | 신고 유형 분류, 담당자 배정 |
| 업로드 API 변경 | 새 영상은 기본 `pending`으로 저장 |
| 공개 피드 필터 | `approved` 영상만 공개 영역에 노출 |

## 7. 쉬운 용어 설명

| 용어 | 설명 |
| --- | --- |
| Moderation | 운영자가 콘텐츠를 검수해서 승인/반려/숨김 처리하는 일 |
| Audit Log | 관리자 행동 기록. 누가 무엇을 바꿨는지 남기는 장부 |
| Server Action | 화면의 버튼이 서버 DB 변경까지 바로 실행하게 하는 Next.js 기능 |
| Status | 데이터의 현재 상태. 예: 구매 완료, 환불, 영상 승인, 신고 처리 완료 |
